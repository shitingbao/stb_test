页面最上方卡片区仅展示最核心的 3 个字段：

(右上角展示当前账单状态，如：待还款)

2.2 账单总金额明细区（卡片组）
在核心数据下方，新增“账单总金额明细：”横向卡片组，用于解释“账单总金额”是如何计算得出的。

计算公式
账单总金额 = 充值/消耗总金额(正) + 现金钱包充值抵扣(负) + 信用额度提前还款(负) + 广告户退款至信用额度(负) + 上月账单结余(负)

卡片字段定义与展示规则
1. 充值总金额 / 消耗总金额
  - 展示规则：绿色字体，带 + 号
  - 释义：该账期内实际发生的广告户充值总额或消耗总额。
2. 现金钱包充值抵扣
  - 展示规则：黑色字体，带 - 号
  - 释义：本账期内，由现金钱包承担的广告户充值金额（不计入信用账单）。
3. 信用额度提前还款
  - 展示规则：黑色字体，带 - 号
  - 释义：在账单正式生成前，用户已充值并提前恢复/抵扣了该账期内已用信用额度的金额。
4. 广告户退款至信用额度
  - 展示规则：黑色字体，带 - 号
  - 释义：本账期内，从广告户退回并直接恢复到信用额度的金额。
5. 上月账单结余
  - 展示规则：黑色字体，带 - 号
  - 释义：上一个账期多余或结转过来，用于抵扣本期账单的金额。
    
2.3 下方明细列表区+导出按钮

7.2 核心字段定义与关系说明

由于系统按 FIFO 顺序还款，一笔转账可能分摊偿还多笔账单。此弹窗用于展示 “在这笔具体的账单视角下，相关的支付记录详情”。

1. 还款金额（蓝字）： 
  - 释义：这笔支付资金中，实际分摊用于偿还 当前查看的这笔账单 的金额。
2. 入账总金额： 
  - 释义：这笔支付在全局维度产生的系统总入账金额。
3. 抵扣信用额度： 
  - 释义：这笔支付全局入账中，所有用于恢复信用额度（偿还历史和当前所有账单）的金额汇总。
4. 进入现金钱包： 
  - 释义：这笔支付全局入账中，在还完欠款后溢出并直接存入现金钱包的金额。
5. 支付方式：
  - 在线支付，银行卡转账，返点钱包还款（如果有），线下转账。
数据逻辑校验关系：
入账总金额 = 抵扣信用额度 + 进入现金钱包
还款金额 ≤ 抵扣信用额度

说明：同一支付编号可在不同账单的支付记录中出现；出现时，它们的【入账总金额】、【抵扣信用额度】、【进入现金钱包】完全一致，仅【还款金额】会根据分摊到各账单的具体数值而不同。
若线下转账未审核，不再任何一笔账单的支付记录内，只有审核通过被分配后，才会计入支付记录

八、资金流转与后台核心规则小结

1. FIFO 自动匹配： 资金到账后，按账单周期从旧到新自动抵扣待还款账单。
2. 现金钱包边界： 仅用于充值广告户。不直接核销账单，而是在账单内作为“现金充值抵扣”项冲减总额。
3. 直接抵扣模式入账口径： 实际系统总入账金额 = 本金 - 手续费 + 返点放大。
4. 新版本账期账单支付时的资金运转逻辑：
  1. 还账单，还账单的金额同时要抵扣可用额度，有余款要进入现金钱包
  2. 抵扣可用额度——无账单情况下本账期内的抵扣可用额度会计入账单抵扣掉
  3. 进入现金钱包。
  4. 走该逻辑的情况：在线支付，返点钱包还款，银行卡转账，线下转账，广告户退款。
  第一种：先账单后还款，且还款金额大于账单金额
  1. 先查看是否有待支付账单，有的话按时间正序抵扣账单。抵扣账单的同时，需要增加对应的可用额度。如果可用额度增加到与授信额度一致，仍旧有剩余，那么进入钱包。
  2. 如果还完所有账单仍旧有剩余金额。进入现金钱包。
  3. 例如：账单金额为1000。当前额度为800/1500。还款1500.那么首先账单1000变为已支付状态。同时可用额度增加700。因为还账单的部分还剩下300，所以现金钱包增加300。因为还款是1500，有500是未还账单直接进入现金钱包的。所以现金钱包余额800
  第二种：先账单后还款，还款金额小于账单金额
  1. 先查看是否有待支付账单，有的话按时间正序抵扣账单。抵扣账单的同时，需要增加对应的可用额度。
  2. 金额不够还完账单，仍旧有账单为待还款状态
  3. 还账单的金额对应增加可用额度。
  第三种：先充值后账单
  1. 无账单情况下，可用额度不够用进行充值（四种随便什么）。如果超出可用额度部分计入现金钱包
  2. 记录下流水明细，月底出账单时，记录对应的信用额度提前还款。账单时扣除。
  3. 例如：月中额度：500/1000。提前充值800。额度变为1000/1000和现金钱包300。记录下信用额度提前还款500。后续如果充值到广告户也会先扣除现金钱包的钱，这部分记录为现金钱包充值扣除。例如后续充值到广告户200。那么现金钱包充值扣除200。
